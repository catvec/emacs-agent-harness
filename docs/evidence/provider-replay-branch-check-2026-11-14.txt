      lisp/modules/harness-provider-responses.el :json frozen
    harness-http-request encodes :json with harness-json-encode
    (lisp/harness-http.el:456-457), so a string is encoded as a JSON
    string literal and the wire body is "{\"model\":...}" rather than
    {"model":...}.

    fallback does the same: (cons (harness-json-encode body) nil) is
    text, handed to :json. The Responses adapter's fallback returns
    the plist, so that path is only wrong when replay is loaded.

What would have caught it (for the owner to add to its own suite)
----------------------------------------------------------------

The transport fake records :json. Assert the type the transport will
see, not the bytes the seam returns:

    ;; what goes on the wire is an object, not a JSON string literal
    (should (listp (plist-get (car harness-replay-test--requests) :json)))
    (should (equal "m" (plist-get (plist-get (car harness-replay-test--requests)
                                               :json) :model)))

or, at the HTTP layer, that the encoded body parses back to the same
plist:

    (should (equal body (harness-json-parse
                         (harness-json-encode (plist-get request :json)))))

Either fails today with (plist-get body :model) => nil, and would pass
once the seam's text reaches the transport as :body, or the adapter
hands over a plist rather than text.

Pub cache repair: a package that lost its files
===============================================

The failure: tool/qr_install.sh stopped in the compile step with

    Error: Error when reading '../../../../.pub-cache/hosted/pub.dev/
    shared_preferences-2.5.6/lib/shared_preferences.dart': No such file or directory
    Target kernel_snapshot_program failed: Exception

right after `flutter pub get` printed "Got dependencies!".  pub counts a package
as installed once its directory and recorded hash are in the pub cache; it never
looks inside.  An earlier agent task had been granted the one directory
~/.pub-cache/hosted/pub.dev/shared_preferences-2.5.6/lib.  In its sandbox the
rest of ~ was an empty tmpfs, so `flutter test` saw a package directory holding
only lib/, tried to reinstall it, and deleted lib/'s real files through the
read-write mount before failing on the mount point ("Deletion failed, path =
'.../shared_preferences-2.5.6' (OS Error: Device or resource busy, errno =
16)").  The package directory, its pubspec.yaml and its hash were left in the
real cache, so every later `pub get` took the package for installed.

How lib/ loses its files, in a throwaway bubblewrap sandbox under a scratch
directory (the harness sandbox's layout: ~ is an empty tmpfs, and the one granted
directory, here pkg-1.0/lib, is bind-mounted into it read-write).  The delete is
Directory.deleteSync(recursive: true) of the Dart 3.13.5 SDK, which is what pub
calls to reinstall a package; it removes the files inside the mount before it
fails on the mount point itself, with the very error the earlier task logged:

== real package directory before:
./pkg-1.0
./pkg-1.0/lib
./pkg-1.0/lib/pkg.dart
./pkg-1.0/lib/src
./pkg-1.0/lib/src/impl.dart
./pkg-1.0/pubspec.yaml
inside the sandbox, the package directory holds: [lib]
delete failed: Deletion failed, OS Error: Device or resource busy, errno = 16
exit=0
== real package directory after (outside the sandbox):
./pkg-1.0
./pkg-1.0/lib
./pkg-1.0/pubspec.yaml

The real directory keeps its pubspec.yaml and an empty lib/, which is what
`pub get` takes for an installed package.

The failure and the fix, reproduced with the real Flutter 3.47.7 SDK (the archive that
tool/install_flutter.sh installs, checksum verified), a scratch PUB_CACHE (no
real ~/.pub-cache was touched), the real tool/qr_install.sh and a fake adb.
There is no Android SDK here, so `flutter build apk` is stood in for by
`flutter build bundle --debug`, which runs the same `pub get` and the same
kernel_snapshot_program step that failed.  `python3 tool/test_qr_tools.py`
(PubCacheCheckTest, PubCacheRepairTest) covers the same flows with a fake
flutter.

Also checked on that cache, with the same SDK:
  - `pub get` leaves alone a package whose lib/ was emptied or removed, or whose
    pubspec.yaml was removed; it downloads again one whose hash file is gone, or
    whose directory is gone.
  - `flutter pub cache repair`, run in the project, reinstalls the 91 packages
    of pubspec.lock in a few seconds.  For a package whose directory is empty
    it exits 69 ("Could not find a file named pubspec.yaml") but removes the
    directory, so the script follows it with `flutter pub get`.
  - Of the packages in the cache, cupertino_icons and
    flutter_plugin_android_lifecycle have no lib/ at all (assets and Android
    code only), and no healthy package has an empty lib/.

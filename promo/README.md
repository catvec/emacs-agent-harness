# Emacs Agent Harness: the promo film

**Plain Emacs. Unreasonable power.** A neon film made as code with
[framefields](https://github.com/gatewai-dev/framefields) (TypeScript, rendered on WebGPU),
with an original score, in which **a module's UI crashes down onto a real Emacs, Emacs
suddenly has it, and you watch it being used**.

The film is 36 seconds, 1920x1080, 30 fps: the plain conversation, then one module, the task
board. Its look is **PRESS**: the capture is the whole screen in **BROADCAST's cool dark Emacs**,
the face is **PAPER's DM Serif Display**, the callout is **RISÓ's die-cut sticker**, the ink is
RISÓ's electric blue `#2b3bff`, and the title is warm white over a **hard blue offset** (no glow, no
blur), set in the empty pane beside the board. The same brand in two other title treatments is cut
as two more full films ([The three PRESS cuts](#the-three-press-cuts)); six other brands are in
[`src/style.ts`](src/style.ts) as stills ([Styles](#styles)). The story, the footage and the clock
are the same in all of them, and the other modules come the same way
([The lineup](#the-lineup)), each one a segment of footage and a few lines of data.

## What it shows

| Time | Act | What happens |
|---|---|---|
| 0:00-0:11 | **Plain** | The harness with **no module but the core** (`harness-enabled-modules` is `nil`): code on the left, a chat on the right, a count of `00`, and in the band below only the key being pressed. A person types *show me what Emacs agent harness can do* and the agent answers with a short list (read and edit files, run a shell and git, search the web, use Emacs). The answer streams in slowly and then sits for three seconds and a half, so it can be read. The camera comes close while they type, then pulls back. |
| 0:11-0:12 | **The fall** | The frame trembles and glitches. The task board, cropped from the real footage, falls onto the left half of the Emacs frame. |
| 0:12 | **Impact** | It lands where the board lives in the real frame: shockwave along the floor, sparks, a flash, the camera shakes, **TASK BOARD** is slammed over the frame, and the count reads `03`. The name sits big on the dimmed frame for two seconds before it docks into the top band. The monitor now shows the footage of the harness *with* the board, so the card that landed is what is there. |
| 0:12-0:32 | **In use** | Real footage, given room. Three tasks are typed into the board and submitted, a beat between each (a keycap says which key). They run side by side, each in its own git worktree; one task's session is opened beside the board; the first to finish waits for review, its report is read, and [Verify] merges it. Each callout sits for two seconds or more. The title says what the module is and docks into the top band; under it, once, is the one-line claim. No config text on screen: at README size it was noise. |
| 0:32-0:36 | **End** | The picture goes dark behind the name: *plain Emacs. unreasonable power.* It holds for four seconds. |

### What is real, and what is not

- **The Emacs is real.** Every pixel of the monitor is `x-export-frames` of the live Emacs frame
  of this checkout's harness, 2400x1350 at Hack 20 pt (149 columns by 40 lines, 74 to a half).
  The chat, the board, the tool calls, the buttons, the merge are the harness's, and
  the tasks are real tasks in real git worktrees of a demo project. Nothing on the monitor is
  drawn, except what is plainly drawn on top: the pointer, keycaps, callouts, titles.
- **The modules are enabled live**, in that one Emacs, with the command a person would run,
  `harness-enable-module`, between two segments of footage (off camera: it compiles a few
  files). The harness runs in the Emacs process for this recording, as it does for the README
  pictures; in the default setup a module's harness-process half loads when that process restarts.
- **The model is a stand-in.** As in the README pictures
  ([`docs/screenshots.md`](../docs/screenshots.md)), a scripted provider takes the
  place of Claude Code, so that the run needs no CLI, no network and no login. It says what
  the story gives it to say; the tools its calls name are the real ones, run on the demo project,
  and what they print is what they printed.
- **Time on screen is the video's.** The recorder runs the harness on a virtual clock (see
  below), so "Writing... 8s" and a task's "3s" mean 8 and 3 seconds of film.
- **Every claim in words is held against the repository** by `npm run check`:
  the module each act enables is one `docs/modules/README.md` lists, and each callout and
  tagline is a passage of the README or a module page.
- **The score is original**, generated by code ([`src/music/`](src/music/README.md)): no
  samples, no third-party audio. It was written without anyone listening to it, so every
  quality claim about it is a measurement.

## Styles

The film's look is data ([`src/style.ts`](src/style.ts)). A style is a brand, not a layout: the
real Emacs capture is **the whole screen** in every one. There is no inset monitor and no padding
around the picture; the title is over the capture, not above it. A brand changes the **grade of the
capture itself** (an ffmpeg filter chain, cached per style under `build/footage/graded/<id>/`, so
the dark UI can read as a cream page, a silver print or a lime duotone), the display face, the
overlay language and the shape of the title. `PROMO_STYLE` picks the brand (default
`press-offset`, the one the film ships in). Every style bakes its own chrome into
`build/baked/<id>/`.

| # | Brand | Frame | Type | Title |
|---|---|---|---|---|
| 01 | **PAPER** | inverted to a warm cream page | DM Serif Display | solid black in a printed title block; editorial rules |
| 02 | **NOIR** | silver print, black bands | Bebas Neue | white caps in a solid black bottom bar |
| 03 | **ACID** | lime duotone | Archivo Black | black words knocked out of a lime slab |
| 04 | **SIGNAL** | cool near-black, a black masthead | JetBrains Mono | small tracked caps in the masthead; the capture is the hero |
| 05 | **BROADCAST** | cool steel, white bars | Space Grotesk | navy type in a white lower third under a white top bar |
| 06 | **RISÓ** | fluoro pink paper | Noto Serif Black | black and blue split, halftone, misregistered rules |
| 07 | **PRESS · FILL** | BROADCAST's cool dark Emacs | DM Serif Display | RISÓ's electric blue, solid |
| 08 | **PRESS · OUTLINE** | the same frame | DM Serif Display | warm white ringed in electric blue |
| 09 | **PRESS · OFFSET** | the same frame | DM Serif Display | warm white over a hard blue offset shadow |

The last three are one brand (PRESS: BROADCAST's Emacs, PAPER's serif, RISÓ's die-cut sticker and
blue) in three title treatments; each of those is a whole film, cut from the same frames and score
([The three PRESS cuts](#the-three-press-cuts)). The other six brands are proposed as their own
1920x1080 still (frame 400, the title slam) and a four-second clip (one second of its card, then the
frame held), so the looks can be compared one at a time.

```sh
PROMO_STYLE=paper npm run prep
PROMO_STYLE=paper FILM_OUT=output/styles/paper npx tsx src/render.ts frames 400
npx tsx src/style-sheet.ts            # -> output/styles/proposals/NN-<id>.png and .mp4
                                      #    plus output/styles-reel.mp4
```

The full film in any brand, from scratch, is one variable away: `PROMO_STYLE=paper scripts/render-all.sh`.

### The three PRESS cuts

One film, three title treatments: the title is the only thing that changes between them, and the
frames and the score are the same. Each is a 36 second 1920x1080 cut.

| Treatment | Title | Cut |
|---|---|---|
| **OFFSET** (ships) | warm white, hard blue shadow offset down-right, no blur | `output/press/press-offset/press-offset.mp4` |
| **OUTLINE** | warm white ringed in blue | `output/press/press-outline/press-outline.mp4` |
| **FILL** | solid blue | `output/press/press-fill/press-fill.mp4` |

```sh
for s in press-offset press-outline press-fill; do
  PROMO_STYLE=$s npm run prep
  PROMO_STYLE=$s FILM_OUT=output/frames-$s npx tsx src/render.ts range 0 1080
  FRAMES=output/frames-$s OUT=output/press/$s/$s.mp4 scripts/encode.sh
done
```

## Rebuild it

You need Node 22+, ffmpeg, git, python3, an Emacs built with Cairo, a display to draw the
Emacs on (Xvfb, or a headless `kwin_wayland` with `Xwayland`, as `scripts/media.sh` uses) and a
Vulkan driver for framefields (a GPU, or a software one, below).

```sh
cd promo
npm ci                      # framefields 2.5.3; only skia-canvas may run an install script (package.json "allowScripts")
scripts/render-all.sh       # footage (if missing) -> check -> sprites -> score (if missing) -> frames -> output/emacs-agent-harness-promo.mp4
```

or step by step:

```sh
capture/capture.sh          # the footage of the real harness -> build/footage/ (about 3 minutes; the first run also compiles the harness)
npm run check               # the film says only true things, and fits its footage
npm run prep                # bake the active style's sprites into build/baked/<style>/ (a few seconds)
npm run music               # the score -> build/score.wav + its QA
scripts/render-all.sh frames   # every frame -> output/frames/ (resumable)
scripts/encode.sh           # -> output/emacs-agent-harness-promo.mp4, poster, contact sheet
```

To look at a moment without rendering the film:

```sh
FILM_SCALE=0.5 npx tsx src/render.ts frames 240 246 262 500    # half-size PNGs -> output/frames-0.5/
npx tsx src/print-cues.ts                                      # the clock, and every cue on it
npx tsx src/render.ts lint                                     # schema validation and framefields' lint
```

## How the footage is recorded (`capture/`)

`capture.sh` starts a private display, a scratch `HOME` with a demo project (the README
pictures' `acme-api`), and a fresh `emacs -Q` that loads `promo-rec.el` (the recorder) and
`promo-story.el` (what the footage shows).

- **A clock of its own.** A frame of footage is one tick of a virtual clock, 30 a second: the
  actions scheduled for that frame run (a key pressed, a click), the scripted agents take one step,
  the world is given a moment to settle, and the frame is exported. Exporting takes a
  quarter of a second, so on the real clock an agent's "Writing... 8s" would run several times
  too fast; the harness reads the time with `float-time`, which the recorder holds still
  between frames and moves 1/30 s on each (off camera it follows the real one).
- **The same on any machine.** After each tick the recorder waits for the processes the harness
  started (a tool, git), for as long as they run, so a busy machine takes longer over a frame and
  records the same frames. This story was recorded three times: all three `footage.json` are
  identical byte for byte, and the frames differ only by a spinner's glyph (spinners run on the
  real clock) and by a step of the merge a frame early or late: of the 936 frames, 726 are
  bit-identical, and the worst of the rest differs in 0.08% of its pixels. (A clean checkout,
  with a cold compile cache, has written the same log, too.)
- **A person's hands.** Typing is real key presses (`execute-kbd-macro`) in a rhythm that is a
  person's (uneven, longer between words, a hesitation now and then) and the same on every run.
  Clicks call what the click would. Where a thing happens at its own pace (a task finishing) the
  story *waits for it* (`promo-rec-when-at`) rather than guessing the frame.
- **It logs what the film needs.** `footage.json` has, per segment, the marks, every character
  typed (the film makes the sound of a key of each), the keys pressed (for keycaps), the clicks
  (for the pointer), and rectangles computed from the real buffers (the lines a card took, the
  window the board lives in), in footage pixels. The film never guesses a coordinate.
- **Segments are one Emacs.** Each segment starts from the state the one before it left, so its
  first frame is the last frame of the one before with the new module's UI added; the film
  crops the new UI out of that first frame and drops it between them.

## How the film is built

```
src/timeline.ts   the clock: 120 BPM, a beat is 15 frames, a bar 60; the acts (from the footage log), the fall and the
                  impact on a downbeat, the sections for the score, and CUES, every moment a sound may answer.
                  The picture AND the score read it.
src/story.ts      the words: the module of each act, its title and line, the modules it enables, and CLAIMS
src/style.ts      the six brands: palette, type, overlay, title lockup and HUD, over a full-screen capture
src/footage.ts    the footage log's types and loader
src/theme.ts      the active style's palette and type, the fonts, and the geometry (the monitor is the
                  2400x1350 footage at 0.72)
src/prep.ts       bakes the film's chrome (the monitor's frame, the falling card, keycaps, pointer, titles, callouts)
src/film.ts       assembles the composition from src/scenes/*
src/scenes/       background, monitor (the footage in a camera), motion (camera, shake, pop, split, beat),
                  crash (the card and the impact), overlays (pointer, highlights, callouts), title, hud, outro
src/kit/          drawing helpers (skia-canvas), layers, keyframe helpers
src/music/        the score (see its README)
src/check.ts      claims against the repository; footage against the layout
src/render.ts     frames | range | grid | lint | count
src/style-sheet.ts  the labelled comparison sheet and the reel's chapter cards
scripts/          dev-env.sh (no-GPU setup), render-all.sh, encode.sh, sync-check.py
capture/          the recorder (Emacs Lisp) and the story it records
assets/fonts/     Anton, Bebas Neue, DM Serif Display, Archivo Black, Space Grotesk,
                  JetBrains Mono, Unbounded and Noto (OFL), Hack (MIT)
```

Things that shaped it:

- **Chrome is baked.** Every hard-edged piece of the film (the monitor's frame, the card, keycaps,
  titles, callouts) is a sprite drawn once with skia-canvas (`npm run prep`) and
  shown as an image. That keeps the edges exactly where they were drawn and costs about nothing.
  Footage, particles, shake and composition-wide effects are cheap.
- **Footage is video.** Each segment is H.264 4:4:4 at CRF 10 (4:2:0 would smear one-pixel text
  edges), played by framefields' `Layer.video`, which is frame-accurate: a segment starts on
  the film frame its layer says. The camera moves and scales the footage's "world" inside the
  monitor, and what is drawn on the footage is in that world, so it follows the camera.
- **What lands is what is there.** The card is a crop of the first frame of the next segment at
  the rectangle the new UI takes. On the frame it lands the monitor switches to that segment, under the
  card, so the card fades into the live thing with nothing to match by eye.

## Adding the next module

1. In `capture/promo-story.el` add a segment after `tasks`: enable the module with
   `promo-story--enable`, open its UI, and script its use by frame (`promo-rec-type-at`,
   `promo-rec-key-at`, `promo-rec-click-at`, `promo-rec-when-at`, callouts and highlights from
   the real buffers).
2. In `src/story.ts` add its `ModuleStory` (title, line, modules, landing rectangle, neon) and a claim
   for each callout; in `src/timeline.ts` add the act to `PLAN` on the bar it lands.
3. `capture/capture.sh`, `npm run check`, `scripts/render-all.sh`. The score reads the same
   timeline, so it follows.

## The lineup

The first cut has the task board. The rest of the film is more of the same, the harness's best
features, each with its UI crashing in and enough footage to see it used (proposed, in this order,
so that the harness gets more powerful as it goes):

1. **Task board** (`tasks`, `merge`): parallel agents, one git worktree each, review, merge. *In this cut.*
2. **Review** (`patch-review`, `review`): a task's changes as a file tree with threads of comments; a comment on a line, the agent's answer.
3. **Supervisor mode** (`supervisor`): an expensive model plans and delegates to cheaper workers, enforced by tools.
4. **Quick search** (`quick-search`, `tasks-search`, `session-search`): say what you want; it finds the command, session or task.
5. **Conversation tree and BTW** (`tree`, `btw`): fork a conversation, ask a side question, see the family.
6. **Insights** (`insights`): a month of work with the agents, in figures and in a written summary.
7. **Remote control** (`acp-remote`): a QR code, and your phone drives the harness.
8. **Companion pet** (`pet`): the creature at the bottom of your chats.

## No GPU

framefields draws with WebGPU (Dawn) on Vulkan; without a GPU it needs Mesa's lavapipe
(Debian/Ubuntu: `apt-get install libvulkan1 mesa-vulkan-drivers`; Arch: `vulkan-swrast`).
If the package is not installed system-wide, unpack it somewhere and point at its ICD
manifest:

```sh
export LAVAPIPE_ICD=/path/to/lvp_icd.json     # read by scripts/dev-env.sh, which sets VK_ICD_FILENAMES
```

(`scripts/dev-env.sh` also uses `build/lavapipe/lvp_icd.json` when that file exists: the
folder is gitignored, and `libvulkan_lvp.so` from Arch's `vulkan-swrast` was copied there with an
ICD manifest naming it.)

This cut was rendered that way, on a 16-core CPU with no GPU: its 1080 frames take about
20 minutes in one pass (several render processes at once were *slower* than one, so
`render-all.sh` runs one), the footage about 5 minutes to record, the encode 15 seconds.

## Checks it comes with

```sh
npm run check       # claims == the repository; footage == the layout
npm run typecheck   # tsc, strict, no unused symbols
npm run lint        # framefields' schema validation and lint of the composition
npm run sync        # reads the finished MP4: frames, fps, audio start, and for the impact the
                    # frame where the picture flashes against the frame where the sound jumps
```
